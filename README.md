# Ручной диктор — tg_suf

Персональный аудиодиктор новостей из выбранных Telegram-каналов. Последовательно проходит каналы, озвучивает текст от старых постов к новым и запоминает, где остановился.

**Статус:** этап 0 — проверяемый локальный прототип. Это ещё **не** Android-приложение и не бот, работающий прямо в Telegram.

[Концепция и архитектура в Notion](https://app.notion.com/p/3fe043746cc681cf91aef9c1020f4876?pvs=204).

## Интеграция с Яндекс Станцией (Алисой)

В разработке два режима:

- **Приватный навык Алисы:** голосовое чтение небольшими фрагментами, команды «Читай», «Дальше», «Пауза», «Продолжи», «Пропусти». История и позиция хранятся в той же SQLite-базе. У Dialogs ограничение **1024 символа** на один TTS-ответ, поэтому это ещё не полностью автоматический поток.
- **Непрерывная очередь через Bluetooth:** запустить браузерный/в будущем Android-плеер и подключить Яндекс Станцию как Bluetooth-колонку. Для автономной работы с выключенным экраном нужен будущий Android-плеер Media3.

Подробная архитектура, ограничения, безопасность, HTTPS, инструкции локального тестирования и настройки приватного навыка: [docs/ALICE.md](docs/ALICE.md).

Для эксперимента с webhook: скопируй `.env.example` в `.env`, задай случайный `ALICE_WEBHOOK_SECRET` (не меньше 32 символов) и `ALICE_ALLOWED_USER_ID`, затем запусти `python -m tg_suf demo` и `python -m tg_suf alice-serve`. Webhook работает только локально на `127.0.0.1:8766`; для Яндекс Диалогов нужен **отдельный HTTPS reverse proxy**. **Не публикуй** неавторизованный `tg_suf serve` на порту 8765.

Это прототип. Реальная Яндекс Станция, авторизация Telegram и внешнее HTTPS-развёртывание ещё не проверены.

## Быстрый старт на Windows 11

Открой PowerShell в папке скачанного проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[telegram]"
python -m tg_suf demo
python -m tg_suf serve
```

Открой http://127.0.0.1:8765 — работает большой Play/Pause, пропуск поста, повтор новости, скорость речи, локальная очередь и прогресс. Если не хочется активировать среду, используй `.\.venv\Scripts\python.exe -m tg_suf demo` и аналогично для других команд.

Для повторного создания демо-очереди с потерей **только текущей позиции**: `python -m tg_suf demo --replace-queue`.

## Реальные Telegram-каналы

Обычный Telegram-бот **не имеет доступа** ко всем подпискам пользователя. Используется личная MTProto-сессия [Telethon](https://docs.telethon.dev/).

1. Получи собственные `api_id` и `api_hash` на [my.telegram.org/apps](https://my.telegram.org/apps). Это не bot token.
2. Скопируй `.env.example` в `.env`, заполни `TG_API_ID` и `TG_API_HASH`. Никому не отправляй эти данные, код входа, пароль 2FA или файл `.session`.
3. В PowerShell выполни:

```powershell
python -m tg_suf login
python -m tg_suf channels
python -m tg_suf sync --limit 20
python -m tg_suf serve
```

Команда `sync` предложит выбрать номера каналов **в нужном порядке**, например `2,1`. Для явно известных ID: `python -m tg_suf sync --ids 123456789,987654321`.

Активную незавершённую очередь программа не заменит случайно. Для замены добавь `--replace-queue`.

**Важно:** вход Telegram из настоящего аккаунта разработчиком не тестировался — нужно пройти его локально. Подключение Telethon к Telegram требует интернета.

## Дополнительные команды

| Команда | Что делает |
| --- | --- |
| `python -m tg_suf demo` | Создать демонстрационные новости без Telegram |
| `python -m tg_suf login` | Войти в Telegram в локальной консоли |
| `python -m tg_suf channels` | Список доступных вещательных каналов |
| `python -m tg_suf sync` | Выбор каналов и сохранение новой очереди |
| `python -m tg_suf status` | Проверить последнюю точку остановки |
| `python -m tg_suf serve` | Запустить локальный веб-плеер |

Тесты не обращаются к Telegram: проверяют порядок новостей, пропуск дублей, паузу, восстановление позиции после переоткрытия SQLite, защиту от старых ревизий и HTTP API.

## Как устроено

```
tg_suf/
  telegram_source.py  # Telegram MTProto: выбранные broadcast-каналы
  storage.py          # SQLite: immutable queue + CAS checkpoint
  cli.py              # login / channels / sync / demo / status / serve
  server.py           # HTTP только на 127.0.0.1
  web/                # браузерный Web Speech API плеер
tests/                # локальные тесты без секретов и сети
.github/workflows/     # GitHub Actions
```

Все локальные данные лежат в `.local/`, включая Telegram-сессию `.local/telegram_user.session`. Папка `.local/` и файл `.env` не должны попадать в Git.

## Ограничения, безопасность и следующие шаги

- Браузерный синтезатор использует Web Speech API. Некоторые браузеры не передают границы слов; возобновление внутри публикации тогда приблизительное. При закрытии окна или выключенном экране воспроизведение не гарантируется.
- Важный checkpoint хранит **смещение в символах**, не точное аудиовремя. Для Android Media3 планируется более точная позиция по аудиофрагментам.
- Сервис специально слушает **только локальный адрес** и не содержит многопользовательской авторизации — публично его размещать нельзя.
- В этом этапе нет загрузки вложений, AI-суммаризации, передачи постов в сторонний облачный TTS или обхода защищённого контента. Для настоящего стороннего Telegram-клиента необходимо отдельно проверить [API Terms](https://core.telegram.org/api/terms) и [лицензирование контента](https://telegram.org/tos/content-licensing).
- Следующий этап: проверить вход и каналы на устройстве пользователя, затем создать нативное Android-приложение на Kotlin/Compose + Media3 с поддержкой фонового воспроизведения.
