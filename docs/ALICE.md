# Яндекс Станция и Алиса: архитектура, ограничения и проверка

## Цель

В конечном виде пользователь говорит **«Алиса, запусти Ручной диктор»** и слышит новости выбранных Telegram-каналов. После остановки он возвращается к прежней новости. Промежуточный этап — **приватный диалоговый навык**; целевой «непрерывный эфир» потребует другого аудиоканала.

**Состояние реализации:** код webhook и тесты объединены в `main` через [PR #1](https://github.com/JohnCook36/tg_suf/pull/1). Это **ещё не опубликованный навык и не подтверждённый запуск на Станции**. Настоящий вход в Telegram и публикация навыка требуют настроенных учётных записей.

## Важное ограничение платформы

По официальной документации [Яндекс Диалогов](https://yandex.ru/dev/dialogs/alice/doc/ru/response) поле `response.tts` и обычный `response.text` ограничены **1024 символами**, а [webhook должен ответить за 4,5 секунды](https://yandex.ru/dev/dialogs/alice/doc/ru/response). В [формате ответа навыка](https://yandex.ru/dev/dialogs/alice/doc/ru/response) нет документированного универсального метода передавать длинный внешний аудиопоток с автопереходом между новостями. `meta.interfaces.audio_player` в *запросе* указывает наличие аудиоплеера у устройства и **не означает**, что навык может управлять им через API.

Результат: навык читает **небольшими фрагментами**; чтобы продолжить после фрагмента, потребуется сказать «Дальше». Навык не знает, дослушана ли предыдущая реплика, поэтому не отмечает её прочитанной, пока не получит явно следующую команду. Если навык закрыть посреди фрагмента, он повторит его при следующем запуске. Это сознательная защита от потери текста.

Собственные аудиофайлы Яндекс Диалогов ограничены 120 секундами, 5 МБ и квотой 1 ГБ. Они **не решают** задачу неограниченного непрерывного радио, а загрузка чужих публикаций как аудиофайлов требует отдельной проверки прав и политики данных: [собственные аудиофайлы](https://yandex.ru/dev/dialogs/alice/doc/ru/resource-sounds-upload).

## Путь A: интерактивный навык (реализован как прототип)

`tg_suf/alice_skill.py` — преобразует команды Алисы в операции над **существующей** локальной очередью SQLite. Не читает Telegram на каждый запрос. Поддерживает:
- запуск, «читай», «продолжи» — озвучить ещё не подтверждённую часть текущего сообщения;
- «дальше» — подтвердить выданный фрагмент и озвучить следующий; после конца поста перейти к следующей новости и следующему каналу;
- «пропусти новость» — пометить весь пост пропущенным и начать следующий;
- «пауза», «стоп» — оставить точку без продвижения;
- «статус» — сколько сообщений пройдено;
- «выход» — завершить навык без потери позиции.

`tg_suf/alice_server.py` — **отдельный** loopback-only HTTP-webhook на порту 8766. Существующий браузерный сервер на 8765 не публиковать. Запрос должен знать длинный секрет в URL **и** совпасть с allowlist пользовательского ID Яндекса. Запросы повторно доставленного одного message_id возвращают прежний ответ из SQLite.

**Ограничения прототипа:** один владелец/одна очередь; не работает с Telegram без предварительной команды `sync`; не обнаруживает конец фактического звучания фрагмента; браузерный и голосовой плееры не рассчитаны на одновременное управление; проверять с реальной Станцией перед релизом. API требует дополнительного security review до доступа сторонних пользователей.

## Путь B: непрерывное радио через Bluetooth (цель следующего этапа)

Официальная [инструкция Яндекса по Bluetooth](https://alice.yandex.ru/support/ru/station/speaker):

1. Сказать Станции «Алиса, включи Bluetooth».
2. Соединить Android-телефон или ПК со Станцией как с Bluetooth-динамиком.
3. Открыть плеер проекта, один раз нажать Play. Воспроизведение аудиопотока и переходы между новостями происходят **на телефоне/ПК**, колонка служит выводом звука.
4. Сохранение прогресса выполняет сам плеер и SQLite. В перспективе — нативное Android-приложение Kotlin/Compose + Media3, чтобы экран мог быть выключен.

Плюсы: непрерывная последовательность постов, нет ограничения 1024 символа на публикацию, естественные пауза и продолжение. Минус: это не полностью автономное чтение самой Алисой, нужен сопряжённый плеер. Возможности голосовых команд на Станции при Bluetooth зависят от модели. Этот путь **реально поддерживается** для передачи аудио, но полноценный Android-фоновый клиент в текущем репозитории ещё не создан.

## Локальная проверка навыка на Windows 11 (без Telegram)

1. Создай виртуальное окружение, установи проект по README.
2. `python -m tg_suf demo` — создаёт три тестовые новости.
3. `copy .env.example .env` (PowerShell: `Copy-Item .env.example .env`).
4. Сгенерируй случайный секрет (например, `python -c "import secrets; print(secrets.token_urlsafe(32))"`), запиши в `.env` как `ALICE_WEBHOOK_SECRET`. Никому его не отправляй.
5. Из официального тестового запроса навыка Яндекс Диалогов возьми `session.user.user_id` и внеси как `ALICE_ALLOWED_USER_ID`. Если такого поля нет, для единственного устройства можно использовать `session.application.application_id` в `ALICE_ALLOWED_APPLICATION_ID`. Это **не** идентификатор Telegram.
6. `python -m tg_suf alice-serve` — запускает webhook только на `127.0.0.1:8766`.
7. Сформируй JSON тестового запроса с `session.skill_id`, `session.session_id`, `session.message_id`, `session.user.user_id`, `request.type = SimpleUtterance` и `request.command = читай`. Отправь POST JSON на `http://127.0.0.1:8766/alice/<ALICE_WEBHOOK_SECRET>`. Для следующего запроса увеличь `message_id`; то же значение означает повтор ранее доставленной команды.

Если указан неверный секрет, сервер вернёт 404; неизвестный пользователь — 403; без конфигурации — 503. Логи не включают секрет или текст новостей.

## Настройка приватного навыка на Яндекс Станции

1. Открой [Яндекс Диалоги](https://dialogs.yandex.ru/development), создай **приватный** навык «Ручной диктор» (если название свободно), выбери поверхности с умными колонками.
2. В настройках backend укажи **HTTPS** endpoint `https://<твой-домен>/alice/<твой-секрет>`. Сертификат должен содержать корректную полную цепочку ([требования](https://yandex.ru/dev/dialogs/alice/doc/ru/publish-settings)).
3. Для публикации из интернета поставь TLS reverse proxy, который перенаправляет **только** путь `/alice/<secret>` на 127.0.0.1:8766. Сам веб-плеер 8765 никогда не проксируй. Не выводи токен пути в access log.
4. У сервера должны быть доступны локальная БД проекта и предварительно подготовленная очередь из `python -m tg_suf sync`. Не копируй Telegram-сессию на чужой shared-hosting.
5. Включи приватный доступ, проверь навык через вкладку «Тестирование», затем на своей колонке. Не гарантировать модерацию без фактического теста. Официально [приватный навык](https://yandex.ru/dev/dialogs/alice/doc/ru/publish-settings) можно использовать на своих авторизованных поверхностях после публикации.

**Важно:** `ALICE_WEBHOOK_SECRET` — секрет в URL, который работает как ключ к личной очереди; защити TLS, конфигурацию и логи прокси. В первую очередь предпочитать `ALICE_ALLOWED_USER_ID` вместо идентификатора приложения. Для публичного сервиса с несколькими людьми нужна полноценная account linking и отдельные пользовательские очереди, а не этот прототип.

## Проверки перед реальным запуском

- [ ] `python -m unittest discover -s tests -v` выполняется.
- [ ] Вошли в Telegram локально, выбрали 2–3 канала и заполнили очередь.
- [ ] Приватный HTTPS webhook отвечает за 4,5 секунды.
- [ ] Тест «Дальше» не пропускает части длинного сообщения.
- [ ] «Пауза» и новая сессия повторяют непрочитанный фрагмент.
- [ ] HTTP GET и незнакомый пользователь не раскрывают текст.
- [ ] Открытие и выход из навыка проверены на конкретной модели Станции.
- [ ] Отдельно проверены ограничения Telegram для неэкспортируемого контента.

## План дальнейшей разработки

1. Проверить навык через Яндекс Диалоги на реальной Станции; скорректировать голосовые фразы и timeout.
2. Упростить настройку каналов через Android-клиент, не через консоль.
3. Собрать Android Media3 playback + Bluetooth для настоящего непрерывного эфира.
4. Добавить выверенную синхронизацию прогресса между Android и Алисой.
5. Исследовать легальный и документированный автономный аудиопуть без телефона; не обещать его, пока он не подтверждён документацией и испытаниями.
